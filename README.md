# بدّلها 🔄

**تطبيق لتبادل الأغراض بين الناس في قطاع غزة، بدل البيع والشراء.**

> أنت تملك ما لا تحتاجه. وغيرك يملك ما تحتاجه. **بدّلها.**

- **التطبيق:** Flutter (Android أولاً، ثم iOS، وتعمل نسخة ويب أيضاً)
- **الخادم:** Supabase (PostgreSQL + Auth + Storage + Realtime)
- **البنية:** Clean Architecture + Repository Pattern + Riverpod

### مبادئ الأمان والخصوصية
- **لا GPS أبداً.** الموقع = محافظة + منطقة يختارها المستخدم.
- **تُحذف بيانات EXIF** (ومنها الموقع) من كل صورة قبل رفعها.
- البريد والهاتف لا يظهران لأي مستخدم.
- كل القواعد تُفرض داخل قاعدة البيانات (RLS + دوال RPC)، وليس في التطبيق فقط. أي عميل معدّل لا يستطيع تجاوزها.
- الحظر لا يُكشف للطرف المحظور.

## 🗂️ هيكل المشروع

```
supabase/
  migrations/      ← مخطط قاعدة البيانات، المنطق، الصلاحيات، البيانات المرجعية
  tests/           ← اختبار دورة التبادل كاملة + قواعد الأمان (PostgreSQL محلي)
lib/
  app/             ← الإقلاع، حقن الاعتماديات (providers)
  core/            ← الثيم، التوجيه، أدوات مشتركة، عناصر واجهة عامة
  features/
    auth/          ← الدخول وحالة الجلسة
    profile/       ← الملف الشخصي والتقييمات
    reference/     ← المحافظات، المناطق، الفئات
    listings/      ← الإعلانات: إضافة، تصفح، بحث، تفاصيل
    offers/        ← عروض التبادل والعروض المعاكسة والإتمام
    chat/          ← المحادثات
    matches/       ← المطابقات
    notifications/ ← الإشعارات
    safety/        ← الإبلاغ والحظر
    admin/         ← لوحة الإشراف
```

كل ميزة مقسّمة إلى `domain` (النماذج) و`data` (المستودعات) و`presentation` (الشاشات). الواجهة لا تتعامل مع Supabase مباشرة، بل عبر واجهات المستودعات، لذلك يمكن تغيير الخادم لاحقاً أو اختبار الشاشات بدون إنترنت.

## 🚀 التشغيل

### 1) إنشاء مشروع Supabase
1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. نفّذ ملفات `supabase/migrations/` **بالترتيب**، إما من:
   - **SQL Editor** في لوحة Supabase (انسخ كل ملف وشغّله)، أو
   - Supabase CLI: `supabase link --project-ref <ref>` ثم `supabase db push`.
3. **Authentication → Providers → Email**: فعّل Email.
4. **Authentication → Email Templates → Magic Link**: أضف رمز الدخول إلى الرسالة:
   ```
   رمز الدخول إلى بدّلها: {{ .Token }}
   ```
5. **Database → Extensions**: فعّل `pg_cron` (لانتهاء الإعلانات والعروض القديمة تلقائياً)، ثم أعد تشغيل آخر جزء من الملف `20261002000002_swap_logic.sql` (كتلة `do $$ ... $$`).
6. لجعل حسابك مشرفاً بعد التسجيل، نفّذ في SQL Editor:
   ```sql
   update profiles set is_admin = true where id = (select id from auth.users where email = 'you@example.com');
   ```

### 2) تشغيل التطبيق
```bash
flutter pub get
flutter run \
  --dart-define=SUPABASE_URL=https://<project>.supabase.co \
  --dart-define=SUPABASE_KEY=<publishable-or-anon-key>
```
المفتاح العام آمن داخل التطبيق لأن الصلاحيات محمية بـ RLS. **لا تضع أبداً مفتاح `service_role` في التطبيق.**

### 3) بناء APK
```bash
flutter build apk --release --split-per-abi --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_KEY=...
```
أو عبر GitHub Actions: أضف `SUPABASE_URL` و`SUPABASE_KEY` في **Settings → Secrets → Actions**، وكل push يبني APK قابلاً للتحميل من صفحة Actions.

> للنشر على Google Play تحتاج مفتاح توقيع خاص (keystore). حالياً يُوقَّع الإصدار بمفتاح التطوير، وهذا مناسب للتجربة والتوزيع المباشر فقط.

## 🧪 الاختبارات

```bash
flutter analyze && flutter test        # منطق التطبيق والواجهة
supabase/tests/run_tests.sh            # قاعدة البيانات (يتطلب PostgreSQL محلياً)
```

اختبار قاعدة البيانات يمر بدورة كاملة بين ثلاثة مستخدمين: إضافة، مطابقة، عرض، عرض معاكس، قبول، محادثة، إتمام، تقييم. ويتحقق كذلك من قواعد الأمان: لا يمكن تعديل إعلان غيرك، ولا قراءة محادثة لست طرفاً فيها، ولا تعيين نفسك مشرفاً، والحظر يعمل في الاتجاهين، والمحظور لا ينشر.
